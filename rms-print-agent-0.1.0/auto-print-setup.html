1. How auto-print works

When a waiter takes an order, the system saves a print job for each ticket. A small program called the print agent runs on the venue's reception PC, receives those jobs and sends them to the printers. It then tells the system whether each one printed.

The print agent is the only thing that prints automatically

Saving an order, adding items, taking payment or placing a room-service order never opens a print window or dialog on any screen. If you want paper, either the agent prints it by itself (auto-print on) or staff press the Print button on the order or bill (auto-print off, or agent offline). The browser is never asked to print on its own, so there is no pop-up to dismiss and no ticket can print twice.

  • Kitchen ticket (KOT) – food items. Bar ticket (BOT) – drink items. Bill – the customer's receipt.
  • The agent starts by itself when the PC starts, with nobody logged in, and keeps its queue on disk. A power cut loses nothing it was already given.
  • If a ticket cannot print, staff see a red NOT PRINTED badge in the top bar and can press Reprint. Items are marked as printed only when the printer is confirmed to have received the ticket.
  • A ticket older than 10 minutes is not printed after the PC comes back; the kitchen should not cook for a table that has moved on. It shows as NOT PRINTED instead.

Which tickets does an order make?

Venue hasWhat you set upResult for each order
One printer for everythingOne printer; Kitchen, Bar and Bills all point to itOne ticket with kitchen and bar items in separate sections
One printer, but separate papers wantedSame, and turn on KOT and BOT on separate papersA KOT and a BOT, both on that printer
A kitchen printer and a bar printerTwo printers; Kitchen points to one, Bar to the otherA KOT on the kitchen printer, a BOT on the bar printer
Only a bar printer that prints bothOne printer, all stations point to itOne ticket (or two papers, if you turn that on)

2. Before you go

Check these first

  • The system is deployed and you can log in to it as an Admin or Manager (adding agents and printers needs the Restaurant Settings "Edit" permission).
  • The restaurant's subscription plan includes the Print Server feature. Without it, the Add print agent and Add printer buttons are refused. Enable it for the plan or restaurant before you travel.
  • The restaurant has the Dining module enabled (printing belongs to it).
  • The reception PC runs Windows 10 or 11, and you know an Administrator login for it.
  • The PC has internet and can reach the system's address in a browser.
  • You have the installer folder rms-print-agent-<version> on a USB drive (see below).
  • You know the system's server address, e.g. https://app.example.com. The settings screen also shows it inside the enrolment command (step 5).

Making the installer folder once, on any Windows machine, by a developer

cd print-agent
npm install
npm run package

This produces print-agent\release\rms-print-agent-<version>\. It contains the agent, everything it needs and its own node.exe, so the venue PC needs no software installed. Copy that whole folder to a USB drive. Reuse the same folder for every venue.

Venue used the old print server?

If the venue was running the older "local print server" (a Node program with a PC address like http://192.168.1.x:4000), run the migration once from the backend folder before the visit, and uninstall the old program afterwards:

npm run migrate-printers -- --dry-run     # shows what would be created
npm run migrate-printers                  # creates the printers

It turns the printer names in that venue's settings into Windows-type printers. It skips venues that already have printers, so running it twice is safe. Section 12 has more.

3. Prepare the printers at the venue

Do this before touching the system. The best test of the hardware is the printer's own self-test, not our software.

Network (Ethernet or Wi-Fi) printers

1

Connect the printer to the router by cable (recommended) or Wi-Fi, and power it on with paper loaded.

2

Print the self-test slip (usually: hold the FEED button while powering on). It lists the printer's IP address. Write it down.

3

Make that IP permanent. If the router hands out a different address after a power cut, printing silently stops. Do one of:

  • In the router, add a DHCP reservation (also called "static lease") for the printer, or
  • Set a fixed IP on the printer itself, outside the router's automatic range.
4

Check the PC can reach it. In a command prompt on the reception PC:

ping 192.168.1.50

You should get replies. The agent sends tickets to port 9100, which almost all receipt printers use. Nothing else needs configuring.

USB printers

1

Plug the printer into the reception PC and install its Windows driver (from the maker, or Windows may do it automatically).

2

Open Settings → Bluetooth & devices → Printers & scanners. Note the printer's name exactly, including capitals and spaces (e.g. POS-80). You will type it in the system later.

3

Open the printer, choose Printer properties → Print Test Page and confirm paper comes out. If it does not, fix the driver or cable first.

Paper width Standard rolls are 80 mm (48 characters per line). Small rolls are 58 mm (32 characters). You will pick this when adding the printer.

4. Add the printers in the system Admin / Manager

Log in to the system in a browser, from any computer, and open Settings → Printing.

1

Add each printer

Press Add printer and fill in:

FieldWhat to enter
NameA label you will recognise, e.g. Kitchen, Bar, Counter. Names are not case-sensitive and must be unique.
How is it connected?Network cable or Wi-Fi or USB cable.
Printer address / Port (network)The IP from the self-test slip. Port 9100 unless the printer's manual says otherwise.
Name in Windows (USB)Exactly as it appears in Windows' Printers & scanners list.
Paper width80 mm or 58 mm.
Cut the paperOn, unless the printer has no cutter.
Check paper first (network)Leave on. The agent asks the printer if it is out of paper or has its cover open, and waits instead of sending a ticket into a printer that cannot print it.

Repeat for every printer (kitchen, bar, counter).

2

Say which printer prints what

Once at least one printer exists, Which printer prints what appears. Choose a printer for each of:

  • Kitchen tickets (KOT) – food items
  • Bar tickets (BOT) – drink items
  • Bills – the customer's receipt

The line above the choices tells you what one order will print: different kitchen and bar printers give two tickets, the same printer gives one.

Untouched defaults are not printers Older settings may show names like Kitchen_Printer marked "(not set up here)". Pick a real printer from the list; those old names do nothing.
3

Set the automation options

SwitchMeaning
Print automaticallyOn for auto-print through the agent. Off means nothing prints by itself and staff use the Print buttons (the agent is not used).
New orders (and room service)Print a ticket when an order is placed.
Items added to a running orderPrint only the new items when more are added to an open table.
KOT and BOT on separate papersFor one shared printer, print kitchen and bar items on separate papers. Hotels (Rooms module) have this on by default. It is locked on when kitchen and bar already have different printers.
Show KOT confirmationAsk the waiter to confirm before a kitchen ticket is sent (optional).

Press Save printing settings.

Nothing is sent to a printer yet The printers are saved on the server and will be sent to the agent as soon as it is installed. Tickets made before that appear as NOT PRINTED with the reason "No printers are set up", never silently lost.

5. Create the print agent code Admin / Manager

1

In Settings → Printing, find Print agent and press Add print agent.

2

Enter a Computer name such as Reception PC and confirm.

3

A box appears with a one-time enrolment code like 7K3M-9QX2-H4TD and the full command to run. Use Copy command and paste it somewhere you can reach from the PC (a note on your phone, an email to yourself).

The code is shown once It works one time and expires after 24 hours. Only a scrambled copy is stored, so it cannot be shown again. If you lose it or it expires, press New code on that agent.

6. Install the agent on the reception PC at the PC, Windows Administrator

1

Copy the folder

Copy the whole rms-print-agent-<version> folder from the USB drive to the PC and rename or place it at:

C:\Program Files\RMS Print Agent

Keep it there; the agent runs from this folder.

2

Open a command prompt as administrator

Start menu → type cmd → right-click Command Prompt → Run as administrator → Yes. The title bar should say "Administrator".

3

Enrol this PC

cd "C:\Program Files\RMS Print Agent"
print-agent enrol --server https://YOUR-SERVER-ADDRESS --code XXXX-XXXX-XXXX

Paste the exact command from the settings screen. Use the server address without /api on the end.

On success it prints Enrolled as "Reception PC" for <restaurant name>. This saves the PC's secret sign-in token (encrypted so it is useless on any other PC) and locks the data folder C:\ProgramData\RMS Print Agent to administrators.

If enrol fails The message is deliberately the same for a wrong, used or expired code. Check you typed it correctly, then press New code and try the new one. Also check the PC can open the server address in a browser.
4

Start it now and at every boot

print-agent install

This creates a Windows scheduled task named RMS Print Agent that runs at startup as the SYSTEM account, so it works with nobody logged in. If it stops, Windows restarts it within a minute.

5

Check it

print-agent status

You want to see: enrolled, installed, running, plus the last lines of the log. Back in the browser at Settings → Printing, the status banner should now read Print agent online.

Printers arrive on their own As soon as the agent connects, the server sends it the printer list. You do not copy or edit any file on the PC. (Advanced: a hand-written printers.json is only used when the server has no printers to send.)

7. Test it

1

Send a test page to every printer

In Settings → Printing, on each printer press Send test page. A short test slip should come out of that printer. The test goes through the agent on purpose, so a pass proves the agent can reach that exact printer.

Check: the text is readable and not cut off at the edges (if it is, the paper width is wrong), and the paper is cut (if not, switch Cut the paper or check the printer's cutter).

2

Place a real order

  1. Take an order with at least one food item and one drink item.
  2. The kitchen/bar ticket(s) should print by themselves within a few seconds, with no dialog on screen.
  3. Add another item to the same table: only the new item should print, marked as additional.
  4. Settle the bill: the receipt should print on the Bills printer, with the invoice number, the BS and AD dates, and the PAN if set.
3

Test the failure path (worth two minutes)

Switch a printer off, place an order that goes to it, wait a few seconds. The NOT PRINTED badge should appear after the agent gives up on that ticket (it retries for up to 10 minutes; to see it sooner, remove the printer from the list in settings and order again). Switch the printer back on, open the badge and press Reprint. This is exactly what the staff will do in real life, so show them.

8. Check power-cut recovery important, do once per venue

Reception PCs here are switched off at night and lose power. Prove the agent survives that before you leave.

  • Reboot without logging in. Restart the PC and do not log in. After about a minute, place an order from a phone or another device. The ticket should print. The banner in settings should show Print agent online.
  • Kill the process. In Task Manager, end node.exe (the agent). It should be back within about a minute. (After a clean stop it returns within five.)
  • Pull the power. Place an order while a printer is switched off so a ticket is queued, then unplug the PC. After power returns the ticket should print once, or show as NOT PRINTED if more than 10 minutes have passed.
  • Folder lock-down. In an administrator prompt: icacls "C:\ProgramData\RMS Print Agent". Only SYSTEM and Administrators should be listed.
  • Printer address still right after a router restart. Restart the router, then send a test page to each network printer.
Rare duplicate A power cut in the exact instant a ticket is printing can produce one duplicate slip. This is accepted: a duplicate is safer than a lost kitchen order.

9. Day-to-day use

What staff will see

WhereWhat it meansWhat to do
Top bar badge NOT PRINTED with a numberThat many tickets failed to print or were too old to print after the PC was off.Open it. For each ticket press Reprint (sends it again as a marked reprint) or Dismiss (the table has moved on; clears it without printing).
Settings → Printing banner: Print agent onlineEverything is working.Nothing.
Banner: Print agent offlineThe PC is off, has no internet, or the agent is stopped. Tickets wait and print when it returns, unless older than 10 minutes.Check the PC and internet. Run print-agent status.
Banner: No print agentNo agent is enrolled. Nothing prints by itself; staff can still use the Print buttons.Install the agent (sections 5 and 6).

Bills and reprints

Printing a bill again from Billing marks it as a copy, as IRD requires: COPY OF ORIGINAL – 1, then 2, and so on. The count increases only when the bill was really sent to the printer. If a bill could not be sent, the screen says so and no copy is counted.

Changing printers later

Add, edit or delete printers in Settings → Printing. Changes reach the agent within seconds; nothing on the PC needs touching. If the router gives a printer a new IP, edit its address here.

Where to look for details

  • Log file: C:\ProgramData\RMS Print Agent\logs\agent.log – what the agent did and why a ticket did not print. It rotates at 5 MB.
  • Run it in a window to watch live: stop the task first (Task Scheduler → End), then in an administrator prompt print-agent run. Press Ctrl+C when done, then start the task again.
  • Settings → Printing shows each agent's last contact and its latest error.
Never leave test mode on Setting the environment variable PRINT_AGENT_DRY_RUN=true makes the agent write tickets to its log instead of printing. It is only for checking an install with no printer wired up. Nothing comes out of the printer while it is on.

11. Restaurant or hotel: what differs

The agent, the printers and the steps above are identical for both. What changes is which modules are enabled on the property and what extra tickets exist.

Restaurant onlyHotel (Rooms enabled)
SetupSections 2–8, once per venue.The same, once per property. If the hotel restaurant is in a separate building with its own PC, enrol a second agent there.
Kitchen and bar papersOne combined ticket unless you turn on KOT and BOT on separate papers or have two printers.KOT and BOT on separate papers is on by default (an explicit setting still wins).
Room serviceNot applicable.A room-service order prints like a table order, with the room (e.g. Room 101) on the Table line of the slip. It follows the New orders (and room service) and Items added to a running order switches. A guest's own order from the room QR code prints the same way and is tagged QR ORDER · ROOM SERVICE.
BillsRestaurant bills print on the Bills printer when paid, if auto-print is on.Same for restaurant bills. A room's tax invoice is created when the stay is settled but does not print by itself: press Print on it in Billing, or print the stay receipt from the settle screen.

Checklist for a hotel

  • Printers added and assigned: Kitchen, Bar (or the same printer for both), Bills (section 4).
  • Print automatically, New orders (and room service) and Items added to a running order are all on.
  • Agent installed, enrolled and showing Print agent online (sections 5–6).
  • Test pass: place a table order and a room-service order; both tickets come out with no dialog on screen (section 7).
  • Front desk knows that room invoices are printed with the Print button.

If the agent is offline

Tickets are saved and wait. They print as soon as the agent reconnects, unless they are older than 10 minutes, in which case they show as NOT PRINTED so staff can choose to reprint. Nothing falls back to the browser. If the kitchen cannot wait, use the Print button on the order.

12. Moving, removing, and old sites

Replacing the reception PC

  1. In Settings → Printing, on that agent press New code.
  2. Install the folder on the new PC and run the new enrol command (section 6).
  3. The old PC is switched off the moment the new one enrols, so you never get two agents printing everything twice.

Stopping or removing an agent

  • On the PC: print-agent uninstall (as administrator) removes it from startup. Settings, queue and log stay.
  • In the system: press Remove on the agent in settings. This disconnects it at once and its token stops working. Use this for a lost or stolen PC.

Venue that used the old local print server

  1. Run npm run migrate-printers -- --dry-run, then without --dry-run (backend folder). Printer names saved in settings become Windows printers in the new list.
  2. Install and enrol the agent as in sections 5 and 6.
  3. Send a test page to each printer.
  4. Uninstall or stop the old print server program and delete any shortcut to it. Browsers also forget the old print-server address automatically.

The migration assumes the old narrow layout (32 characters). If a venue has 80 mm paper, edit the printer afterwards and choose 80 mm.

Rules to remember

  • Enrolment code: one use, 24 hours, shown once.
  • Tickets older than 10 minutes are never printed late; they appear as NOT PRINTED.
  • A failing print is retried with growing delays (2 s up to 30 s) for up to 10 minutes, then reported failed.
  • Give every network printer a permanent IP address.
  • One agent per venue PC; a new enrolment replaces the old one.
  • Do the power-cut checks in section 8 at the first install at each venue.
